# 0006 — 索引发布门禁 fail-closed，且把评估报告当作不可信输入

- **状态**：accepted
- **记录日期**：2026-10-12
- **相关规范**：[backend/rag-retrieval-contract.md](../backend/rag-retrieval-contract.md)、`backend/agent/jobs/indexer/gate.py`

## 背景

一套新索引在上线前要证明自己够格：它需要在多份异构评估（质量、容量、评测、延迟、人工）上达标。这些报告由离线任务生成，格式各异，且可能缺失、陈旧或被误改。

## 决策

门禁**刻意把报告视为不可信输入**（`gate.py` 明确不导入离线评估包），要求同一 `indexVersion/profileVersion` 的多份报告**全部在场**且字段一致、阈值达标，任一缺失/不一致/不达标即 fail-closed。评测必须显式为 `RELEASE_CANDIDATE`（`SHADOW_ONLY` 或缺状态都不能激活），必需评测通过数与总数必须严格等于约定值且自洽。门禁通过后**仍需人工确认**才允许切换激活指针。

## 备选方案

1. **自动通过 + 事后告警。** 未采纳——索引是模型回答所依赖的事实边界，坏索引会静默污染所有回答，且上线后难以归因。
2. **fail-closed + 人工确认（采纳）。** 宁可挡住一次合法发布，也不放行一次坏索引。

## 后果

**正面**

- 坏索引无法在报告不全或状态未明时上线；发布是可审计的显式动作。
- 报告被视为外部输入，防止「本地存在一份看似合格的报告」被当成通过凭据。

**代价**

- 运维门槛高：少一份报告、一个字段命名不符、状态写成 `SHADOW_ONLY` 都会挡住发布。
- 无法快速试错式上线；每次发布都要走完整评估。

**约束**

- 不得为「加快发布」而放宽必需字段或阈值；不得把人工确认省略为自动激活。
