# 0020 — 数据来源限 Bangumi v0 官方 API，原始快照留存但不分发

- **状态**：accepted
- **记录日期**：2026-10-12
- **相关规范**：[backend/database-guidelines.md](../backend/database-guidelines.md)、`app/adapters/` 的 Bangumi 适配

## 背景

项目的番剧数据来自 Bangumi。获取方式可以是公开页面抓取，也可以是官方 API。抓回的原始数据如何处置，涉及上游的版权与使用条款。

## 决策

- **只使用 Bangumi v0 官方 API** 作为数据来源（带固定 User-Agent 标识），不做页面抓取。
- **原始响应快照留存**（压缩后存私有桶）以便排障与回溯，但**不再分发**——它存放在与公开封面**不同的私有桶**中（见 [ADR 0003](./0003-separate-public-and-private-minio-buckets.md)）。
- 派生出的公开数据（条目、封面等）按上游条款对外提供。

## 备选方案

1. **抓取公开网页。** 未采纳——不稳定、违背上游意愿、且无法获得稳定结构。
2. **只走官方 API，不留快照。** 未采纳——失去排障时的原始证据（「当时上游到底返回了什么」）。
3. **官方 API + 私有快照留存（采纳）。** 兼顾合规与可回溯。

## 后果

**正面**

- 数据来源合规、稳定、有稳定的响应结构。
- 排障时可回查原始响应，不必重放请求（上游内容可能已变）。

**代价与约束**

- 数据可得性受上游 API 可用性与配额约束；上游限流会直接影响导入。
- 快照**不得**与公开资源混放，必须始终留在私有桶——这是 [ADR 0003] 双桶结构存在的直接原因。
- 用户本机代理（如 fake-IP 模式）可能劫持上游域名，导致离线任务随机超时；运行离线任务时需保证真实网络路径。

**约束**

- 不得把原始快照放入公开桶或对外提供。
- 不得改为抓取模式；上游接口变更时同步适配层，而非绕过 API。
