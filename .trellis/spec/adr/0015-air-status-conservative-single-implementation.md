# 0015 — 播出状态推断收敛为单一保守实现，绝不从日期直接判「已完结」

- **状态**：accepted
- **记录日期**：2026-10-12
- **相关规范**：`app/rag/air_status.py`、[backend/agent-guidelines.md](../backend/agent-guidelines.md)

## 背景

「这部番完结了吗」依赖播出状态。系统里曾有**两份互相矛盾**的推断规则：过滤侧（`retrieval._infer_air_status_name`）把「无权威状态的过去日期」判为 `FINISHED`，输出侧（`use_case._infer_air_status`）判为 `UNKNOWN`。于是同一个作品在两处得到不同状态。

根因是一条错误的隐含假设：单个首播日期可以证明作品已完结。

## 决策

把规则**收敛为一份**，集中在单一函数 `infer_air_status` 中，两处调用点必须复用它、**禁止内联第二份判断**。规则本身取**保守**语义：优先采用权威 `airStatus`；无权威状态时按日期保守推断——未来日期 → `UPCOMING`，过去或无法解析的日期 → `UNKNOWN`；**绝不返回 `FINISHED`**。单个首播日期不足以证明已完结（作品可能被腰斩、可能仍在连载）。

## 备选方案

1. **保留两份，各自修到「一致」。** 未采纳——两处规则分裂正是问题根源，靠纪律维持一致不可靠。
2. **单实现 + 保守语义（采纳）。**

## 后果

**正面**

- 状态的过滤与输出使用同一真相，不再自相矛盾。
- 保守语义杜绝了「把连载中的作品当作已完结」这一误导性错误。

**代价**

- 真正已完结但无权威 `airStatus` 的作品会停在 `UNKNOWN`，而非 `FINISHED`；这是有意接受的信息损失（宁可不知道，不可错答）。

**约束**

- 禁止在消费方内联第二份播出状态判断；所有调用点走 `infer_air_status`。回归见 `tests/rag/test_evidence_contract.py`。
