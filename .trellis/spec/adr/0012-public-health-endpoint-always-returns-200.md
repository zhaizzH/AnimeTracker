# 0012 — 公共健康检查始终返回 HTTP 200，降级在响应体表达

- **状态**：accepted
- **记录日期**：2026-10-12
- **相关规范**：`app/api/health.py`、[backend/error-handling.md](../backend/error-handling.md)

## 背景

后端有一条明确规则：「HTTP 状态码必须与错误码一致」。依赖降级时，按该规则应当返回 5xx。

## 决策

`GET /api/client/agent/health` **始终返回 HTTP 200**，降级在响应体内表达。这是对上述规则的**有意例外**，理由写在代码 docstring 中：它是**诊断接口**而非业务响应，且没有常驻调用方依赖其状态码。响应体的 `checks` 只含有限枚举 `ok`/`down`/`disabled`，且**绝不含异常文本**，以免泄漏上游响应体与连接串；被禁用的功能开关是 `disabled`，不是 `down`。

## 备选方案

1. **遵循通用规则，降级返回 5xx。** 未采纳——会让该接口被通用错误处理接管，把「诊断信息」变成「一个错误」，也诱使调用方以状态码代替读取诊断细节。
2. **恒 200 + 体内表达（采纳）**，并把隐私红线编码进 `checks` 的取值域。

## 后果

**正面**

- 诊断接口的消费者始终能拿到结构化体检结果，不受状态码分支影响。
- 取值域封闭（`ok`/`down`/`disabled`）从结构上防止泄漏上游细节。

**代价**

- 违反通用规则，**必须显式说明**，否则后来者会「按规范」把它改成返回错误码——那会破坏契约（已有测试钉住恒 200）。
- 需要与相关的一处「刻意的两层认证不一致」（代理层要求认证、直连 `:8090` 匿名）一并理解：这些都是有意的例外，不是疏漏。

**约束**

- 改动该端点时必须保持恒 200；不得把异常文本放进 `checks`。
