# 0017 — 前端技术栈中途从 Vue 3 迁移到 React，接受已写代码作废

- **状态**：accepted
- **记录日期**：2026-10-12
- **相关规范**：[frontend/index.md](../frontend/index.md)
- **证据**：`docs/retrospective/项目复盘.md`（含提交 `efb68e0`、`3e64303`）；`frontend/` 现状

## 背景

项目前半程的前端以 Vue 3 + Pinia 编写（登录、注册、仪表盘等页面已完成）。中途决定改用 React 18 重写，**前半程的 Vue 页面全部作废**（这就是一次已沉没成本的主动放弃）。

> 注：本节记录的是历史决策；具体的迁移日期与提交区间以 `docs/retrospective/项目复盘.md` 为准，本 ADR 不重复可能过期的细节。

## 决策

采纳 React 18 作为前端技术栈，放弃已有的 Vue 页面并重写。随后用户端与管理端统一为 **shadcn/ui + Tailwind CSS v4 + shadcn 令牌**（已全面移除 Ant Design）。

## 备选方案

1. **留在 Vue 3。** 未采纳——Vue 生态在组件库/设计系统上与本项目选定的方向（shadcn/ui 那套「组件代码即源码、本地可改」的模式）匹配度较低。
2. **迁移到 React 并统一 UI 栈（采纳）。**

## 后果

**正面**

- 两端（client/admin）统一技术栈与设计系统，组件规范、UI 原语契约、令牌体系只需维护一套。
- 获得 shadcn/ui「组件是本地代码、可随意改」的可控性，不再被上游 UI 库的样式与升级周期绑住。

**代价**

- 前半程 Vue 页面作废重写，沉没成本真实发生。
- 迁移过程中遗留命名/结构痕迹，需要后续清理（例如 `--od-*` 令牌层已退场，但部分历史债务仍在收敛）。

**约束**

- 前端只有一种技术栈；不得在仓库内复活 Vue，也不得重新引入 Ant Design（构建产物出现 `vendor-antd*` 视为回归）。
