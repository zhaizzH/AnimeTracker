# 设计方案

## 规范修改
主要修改 .trellis/spec/backend/quality-guidelines.md 的 Java Javadoc 章节，必要时同步 backend/index.md 摘要
类型写职责，字段写业务含义，方法直接写行为，方法体解释原因；删除“执行某某业务流程”等无信息套话，不把“用于”等普通词一律列为禁词
每段说明和每个标签说明末尾不加句号，内部句间标点正常使用。保留声明覆盖和必要标签，不按行数裁剪契约

## 表达示例
```java
/** 刷新会话有效期，单位为秒 */
private long refreshTtlSeconds;

/**
 * 撤销用户的全部刷新会话
 * @param userId 用户 ID
 */
void revokeAll(Long userId);
```
这是格式示意，不新增业务接口；正式规范优先采用已核对实现的现有声明

## 检查器兼容
当前 CheckJavadoc.java 不要求末尾句号，默认保持核心扫描逻辑
在 test_check_javadoc.py 添加无末尾句号的合法类型、字段、方法和标签样例，保留旧句号兼容及缺文档、错标签、机械模板等负例
不新增全库末尾句号拒绝规则，避免强迫本任务迁移所有存量。新写作风格由规范和人工审查落实，自然表达不能仅靠禁词扫描判断

## 风险与回滚
精简可能误删空值、单位、异常条件，审查时逐项对照实现
旧存量注释仍可能带句号，本任务不宣称完成全库迁移
回滚仅涉及本任务规范和检查器测试，不改变运行时业务行为
