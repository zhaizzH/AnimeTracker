# 设计方案

## 修改边界

行为差距是后端 Java 注释仍普遍使用中文句号，而规范要求中文说明末尾不加句号。句号只存在于注释文本时才修改，避免触碰字符串、SQL、日志消息和代码

## 实施方式

使用脚本读取 backend/business/**/*.java，仅在 Java 注释上下文中识别行末中文句号，生成候选差异后逐项检查。优先覆盖 Javadoc；方法体普通中文注释也遵循项目自然表达约定。保留段落内部句号、枚举值、URL、版本号和中文字符串

不修改 CheckJavadoc.java 的语义规则；它继续负责声明覆盖、标签和机械模板检查。用现有全量工具确认迁移没有改变 Javadoc 可解析性

## 风险与回滚

批量替换可能误触碰字符串或代码值，因此每批只提交注释行差异，并用 git diff、检查器和 Maven 验证。若发现误改，按文件回退该批次后缩小匹配范围，不使用破坏性 reset

## 范围外

不迁移 Python、前端注释，不改注释内容语义，不新增检查器禁止末尾句号的硬门禁，不调整模块职责或业务实现
