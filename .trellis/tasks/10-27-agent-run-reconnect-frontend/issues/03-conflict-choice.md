# 03: 同一会话已有一条回答在跑时，让用户选

**What to build:** 用户在一个已经有回答正在生成的会话里再发一条，后端拒绝并发并告诉前端「当前活跃的是哪个 run」。前端不静默失败、不吞掉用户输入，而是给三个明确选项：打断那一条并插入自己这条、等那一条跑完、取消本次发送。

**Blocked by:** 01（需要一个已被验证的「停掉指定 run」通路）

**Status:** ready-for-agent

- [ ] 冲突错误携带后端给出的活跃 run 标识，调用方不需要解析文案字符串
- [ ] 收到冲突时进入选择态，不写入半条 assistant 气泡、不丢用户输入
- [ ] 选「打断并插入」：先停掉活跃 run，再用同一段文本重新发送
- [ ] 选「等待」：不发任何请求，退出选择态
- [ ] 取消选择面板：不发请求，也不留下空气泡
- [ ] client 与 admin 两个入口都有该面板，交互一致
- [ ] 有测试断言三条分支各自的请求次数（打断=2 次、等待=1 次且不含重发、取消=0 次重发）
