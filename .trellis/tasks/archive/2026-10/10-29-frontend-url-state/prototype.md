# 前端原型：agent 导航时的界面形态

> **本文件是 PRD 的前置审查物**。`prd.md` 暂冻结，原型审过再定稿。
> 只涉及两个可视变化：① `/anime` 筛选可入 URL ② 浮层在 agent 导航时保持打开。

## 0. 已有事实（决定原型不必设计的部分）

- `AgentChatProvider` 挂在 `layouts/ClientLayout.tsx`，**全路由常驻**，`useAgentChat` 的会话 state 不随路由丢失。
- 浮层 `AIAssistantFloat` 与 `/agent` 页**共享同一份会话**（都走 `useClientAgentChat()`）。所以不需要做「会话保存/恢复」。
- 浮层尺寸：`fixed right-6 bottom-24`，`h-[28rem] w-[22rem]`，`max-w-[calc(100vw-3rem)]`。
- 浮层现有 header：`AI助手` 标题 + 「打开完整助手」+「关闭」两个按钮。
- `/agent` 路由下浮层返回 `null`（不重复渲染）。

**原型只需回答三个问题**：导航时面板什么样、用户怎么知道发生了跳转、窄屏怎么办。

---

## 1. 主形态：agent 导航，浮层保持

用户说「给我看 2022 年的番」之后：

```
┌───────────────────────────────────────────────────────────────┐
│  AnimeTracker        番剧索引  放送日程  我的收藏   [头像]      │
├───────────────────────────────────────────────────────────────┤
│                                                               │
│  番剧索引                                      ┌──────────────┐│
│  ┌──────────────────────────────────────────┐ │ AI助手    ⛶ ✕││
│  │ [关键词      ][搜索] [2022▾][全部星期▾]    │ │──────────────││
│  │ [评分▾][降序▾]                             │ │ 已为你打开   ││
│  └──────────────────────────────────────────┘ │ 2022 年番剧  ││
│                                               │ 索引，年份筛 ││
│  ┌────┐ ┌────┐ ┌────┐ ┌────┐                  │ 选已生效。   ││
│  │封面│ │封面│ │封面│ │封面│                  │              ││
│  └────┘ └────┘ └────┘ └────┘                  │ 你说：       ││
│  ┌────┐ ┌────┐ ┌────┐ ┌────┐                  │ ┌──────────┐ ││
│  │封面│ │封面│ │封面│ │封面│                  │ │输入…  ➤ │ ││
```

地址栏：`/anime?year=2022`

**要点**：
- 左侧页面**真的变成筛选后的结果**，这是特性价值所在。
- 浮层**不遮筛选栏**。当前 `right-6 bottom-24` + `w-[22rem]` 在 1400px 容器下会压住右侧封面列，但不压住顶部筛选行。可接受，不改位置。
- 浮层 header 不变，不加新按钮。

## 2. 三个待审的界面决策

### 2.1 用户怎么知道「是 agent 跳的页」？

**方案 A：浮层内一条系统提示（推荐）**
```
│ ⚡ 已跳转到「番剧索引 · 2022 年」        │
```
插在消息流里，样式同现有 `function_call` 工具行（小字、muted），**不是 assistant 正文**。
- 优点：不打断流式回答；与「路由即工具」的心智一致；实现上就是 `ui_action` 渲染成一行，不动消息模型。
- 缺点：用户若只看页面不看浮层，可能没注意。

**方案 B：页面顶部 toast**
- 优点：看得见。
- 缺点：与刚做的「提示拆成 toast 与会话横幅两条通道」规范冲突——那次的结论是一次性提示才走 toast，导航反馈属于会话内状态，应留在会话里。

**方案 C：什么都不显示**
- 缺点：页面突然变化而无解释，用户会以为点错了。

➡️ **A**。若后续实测发现用户没感知，再加 toast，不一期做。

### 2.2 窄屏（< 768px）浮层怎么办？

当前浮层 `w-[22rem]` + `max-w-[calc(100vw-3rem)]`，在 375px 屏上占 327px ≈ **87% 屏宽**，跳转后新页面几乎全被挡住。

**方案 A：窄屏下 agent 导航自动收起浮层为气泡（推荐）**
```
┌─────────────────┐
│  番剧索引        │
│  [2022▾][星期▾] │
│  ┌───┐ ┌───┐    │
│  │封面│ │封面│   │
│  └───┘ └───┘    │
│            [🤖¹]│  ← 气泡带未读标记
└─────────────────┘
```
- 优点：新页面完整可见，这正是导航的目的。
- 缺点：用户需再点一次才能继续对话；但窄屏下这是必然取舍。

**方案 B：窄屏浮层改全屏抽屉**
- 缺点：跳转后页面仍不可见，特性失效。

➡️ **A**。断点用 `md`（768px），与项目现有 Tailwind 用法一致。

### 2.3 「打开完整助手」跳 `/agent` 时算不算 agent 导航？

现状 `openFullAgent()` 里 `setOpen(false); navigate('/agent')`。
- 这是**用户主动点击**，不是 agent 导航 → 照常关浮层（反正 `/agent` 下浮层本来返回 `null`）。
- 不受影响，原型无需改动。

## 3. `/anime` 筛选 URL 化的可视变化

**界面本身零变化**。唯一可感知的是地址栏：

| 操作 | 现在 | 改后 |
|---|---|---|
| 选年份 2022 | `/anime`（年份只在内存） | `/anime?year=2022&page=1` |
| 选星期五 | `/anime` | `/anime?weekday=5&page=1` |
| 改排序为升序 | `/anime` | `/anime?order=asc&page=1` |
| 默认排序 | `/anime` | `/anime`（默认值不入 URL） |

筛选栏布局、控件、交互**完全不动**：

```
┌──────────────────────────────────────────────────────┐
│ [关键词          ] [搜索]                            │
│ [全部年份▾] [全部星期▾] [评分▾] [降序▾]              │
└──────────────────────────────────────────────────────┘
```

**副作用（正向）**：刷新不丢筛选；可以把筛选结果链接发给别人。

## 4. 复合指令「写入 + 导航」的形态

「把这部加入想看，然后打开我的收藏」：

```
阶段 1（预览，不跳转）           阶段 2（用户确认后）
┌──────────────┐                ┌──────────────────────────┐
│ 将加入想看：  │                │ 我的收藏                  │
│ 《孤独摇滚》  │      ──►       │ [想看][看过][在看▾][搁置] │
│              │                │                          │
│ 确认执行吗？  │                │ 《孤独摇滚》 想看  0/12  │
│ [确认] [取消] │                │              ┌──────────┐│
└──────────────┘                │              │ ✓ 已加入 ││
                                │              │ ⚡ 已跳转 ││
                                │              └──────────┘│
                                └──────────────────────────┘
```

- **预览阶段绝不跳转**——用户取消就什么都没发生。
- 确认 → 写成功 → 才跳转。顺序由后端图保证，前端只是被动接收 `ui_action`。

## 5. 明确不做的界面

- 不做「预览目标页面」的缩略图或内嵌 iframe。
- 不做浮层拖拽/缩放。
- 不做导航历史（「返回上一页」按钮）——浏览器后退已够用。
- 不在页面上加「AI 正在操作」的全局遮罩或 loading。
- 不做 macOS 式的大面板常驻侧栏（那是另一次布局改造，不属于本特性）。

## 7. 审查结论（2026-10-29）

已用真实可跑原型验证（`frontend/client/prototype.html`，V1/V2/V3 三变体，CDP 实点驱动），结论：

| 审查点 | 结论 |
|---|---|
| §2.1 导航反馈形态 | **采用 V1**：浮层内一行系统提示（`⚡ 已跳转到「番剧索引 · 2022 年」`），不用 toast |
| §1 浮层位置与尺寸 | **完全不动**，`right-6 bottom-24 h-[28rem] w-[22rem]` 保持 |
| §2.2 窄屏方案 | **否掉 V3**（自动收起为气泡），一期不做 |
| §3 `/anime` 界面 | 接受「界面本身零变化」；但**界面必须随操作真实变化**（见下） |
| §5 五项不做 | 全部确认不做 |

### 新增的硬要求：界面随操作真实变化

审查中明确：URL 只是状态的载体，**不允许出现「地址栏变了但界面没变」**。已写入 `prd.md` 的四条可验证项：

1. 筛选控件自身显示值与新状态一致
2. 结果列表真实重查并替换（断言卡片集合不同，不能只断言 URL）
3. 重查期间显示加载态，结束后不残留旧列表
4. 无结果时显示空态而非上一次结果

### 原型实测记录

- V1：年份下拉真变 2022，标题变「共 8 部作品」，卡片换成 2022 组，浮层出现系统提示，URL 条变 `/anime?year=2022&page=1`
- 复合指令：预览阶段 URL 仍 `/anime?page=1` 不跳转；点确认后 → `/my-collections?tab=want&page=1`，计数 3→4
- 生产文件零改动，vite error 计数 0

原型文件保留在 `frontend/client/src/prototype/`，供后续 agent 侧任务参考导航反馈的视觉形态。
