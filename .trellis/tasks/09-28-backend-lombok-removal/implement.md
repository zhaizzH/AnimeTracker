# Implementation Plan

Revised 2026-09-28 (Phase 2 → Phase 1 correction). Expansion now uses Lombok's own `delombok` instead of line-by-line manual transcription, and a Javadoc workstream is added because the checker inspects every handwritten method. See `prd.md` Progress Ledger for the measurements behind both changes.

## Ordered checklist

1. **Capture behavior before editing**
   - Run the Business Maven test baseline and record the actual result for this task; do not reuse historical spec counts. (Recorded: 95 tests, 0 failures, 0 errors.)
   - Inventory all production Lombok imports/annotations and Lombok POM/README declarations. Preserve a machine-checkable before/after count.
   - Snapshot the pre-migration public surface with `javap -p` for every Lombok-bearing class, so R3 equivalence is proven by comparison rather than review.
   - Add targeted characterization tests for representative `@Data` equality/hash/toString behavior, `SubjectDetailVO` superclass equality, builder default/explicit-null behavior, Jackson JSON round-trip of `ProgressPreviewSnapshot`, and relevant Spring binding/constructor signatures. Reuse existing coverage rather than duplicating broad tests.
2. **Expand Lombok-generated members with `delombok`**
   - Run `delombok` over all nine modules' `src/main/java` with the reactor classpath; it is a one-off migration tool and adds no build-time code-generation dependency (R2).
   - Clean the output: remove the `// Generated by delombok at ...` header, drop every `@java.lang.SuppressWarnings("all")`, and de-qualify the fully-qualified `java.lang.*` references delombok emits.
   - Rename delombok's internal identifiers so the result reads as ordinary Java: `$default$foo` field-default helpers, and the `foo$set` / `foo$value` builder state fields.
   - Preserve CRLF line endings on files that currently use them; do not let an editor rewrite a file's newline style.
   - Confirm every Lombok import and annotation is gone from the expanded sources while unrelated annotations (`@JsonInclude`, Bean Validation, Jackson, MyBatis) stay on their current targets.
3. **Write Javadoc for every migrated member**
   - `CheckJavadoc.java` inspects every method, constructor, field and type, so the expansion pushes roughly 2000 constraints into scope. Accessors delombok copies field comments onto still lack `@param`/`@return`; `equals`, `hashCode`, `toString`, `canEqual`, constructors and builder methods start with none.
   - Derive accessor Javadoc from the real field semantics (units, null meaning, valid ranges) rather than mechanical "获取 X 字段" templates, which `quality-guidelines.md` rejects on review even though they would satisfy the automated check.
   - Validate incrementally with `python backend/business/tools/check_javadoc.py`; it needs Surefire reports present, so run it after a test pass.
4. **Replace generated behavior in service and framework modules**
   - Add explicit constructors for required/all/no-arg constructor annotations without changing injection signatures.
   - Replace `@Slf4j` with explicit SLF4J logger fields; remove actual Lombok imports only and preserve Spring/Jakarta annotations with similar names.
   - Cover modules `common`, `infrastructure`, `auth`, `log`, `agent`, `client`, `admin`, and `app`.
5. **Remove dependency/config references**
   - Delete the Lombok managed artifact/version from the parent POM, every direct Lombok dependency from all nine child POMs, and the `backend/business/README.md` Lombok dependency row. Verify no Lombok dependency remains in any Business POM.
   - Search the full backend/business tree for stale annotation, import, dependency, plugin, or documentation references; distinguish any task-artifact discussion from runtime/build references.
6. **Run targeted and full verification**
   - Run existing and new tests during the rewrite, then run full `mvn -B clean test -f backend/business/pom.xml` after dependency removal.
   - Re-run `javap -p` and diff against the pre-migration snapshot to prove accessor, constructor and builder equivalence.
   - Run `python backend/business/tools/check_javadoc.py` and `python backend/business/tools/test_check_javadoc.py`.
   - Search production/test Java and Maven/docs for `lombok` and confirm zero remaining backend runtime/build references.
   - Review OpenAPI and schema diffs to verify neither changed; review git diff to ensure unrelated pre-existing worktree changes are untouched.

## Review gates and rollback points

- Do not remove Maven Lombok dependencies until all Lombok-generated source references have been replaced and the reactor compiles.
- After `pojo` expansion, run its and dependent module tests before broad continuation; after module-wide source expansion, run the reactor tests before POM cleanup.
- Check all constructor signatures and builder chains by compilation plus targeted tests; compilation alone will not prove defaults/equality/JSON compatibility.
- Do not make unrelated security decisions such as changing password `toString` behavior under this task without separate approval.
- If behavior changes unexpectedly, stop dependency cleanup and repair the handwritten equivalent; rollback only this task's changes without overwriting pre-existing dirty files.
