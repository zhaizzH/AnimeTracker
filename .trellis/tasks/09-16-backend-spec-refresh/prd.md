# 刷新 Backend Trellis 规范

## Goal

根据当前 AnimeTracker 后端源码、测试、模块依赖和运行配置刷新 `.trellis/spec/backend` 及共享跨层指南。规范必须反映当前实现，同时保留迁移过程、历史测试证据和目标设计，并明确区分三者

## Scope

- 更新 Backend 架构、目录、异常、质量与跨层指南
- 以 `backend/business` 的 POM、Java 源码、架构边界测试、资源配置和 CI 为事实来源
- 合并同主题内容到现有文档，减少重复文件，不新增没有稳定主题归属的文档
- 保留历史内容，但用“历史记录”或“迁移前”标记，并补充当前实现说明
- 仅修改 Trellis 规范与本任务记录，不修改业务代码、接口行为或前端规范

## Acceptance Criteria

- [x] 模块职责、依赖上限、Converter 归属、POJO 跨模块对象归属与 HTTP 异常适配位置和当前 POM、源码、架构边界测试一致
- [x] 当前资源文件、配置入口、质量门禁和注释规范均有源码或命令证据；过时表述被改正
- [x] 历史迁移记录保留且明确标为历史，不会被读作当前约束
- [x] 同主题内容优先在既有文档内合并，目录索引、相对链接和文件路径有效
- [x] `.trellis/spec` 无未处理的 TBD、占位文本或失效链接；任务记录包含验证结果
