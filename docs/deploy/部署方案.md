## 3. 磁盘与内存调优（本次实施）

### 3.1 新增 50G 数据盘

```
sda 30G  →  /                  系统盘 + Docker volumes
sdb 50G  →  /opt/animetracker  ext4，UUID 挂载，defaults,noatime
```

### 3.2 swap 与 swappiness

```
/swapfile                  2G  （原有，在 sda）
/opt/animetracker/swapfile 4G  （新增，在 sdb）
vm.swappiness=10               （原为 100，激进换出会拖垮 JVM 与 SSE）
```

`/etc/sysctl.d/99-animetracker.conf` 持久化；`/etc/fstab` 追加两行（UUID + swapfile）。

> **实证风险**：`swappiness=100` 时 `pswpout` 4 天累计 77GB，说明早已在剧烈 thrashing。
> 2026-10-03 已发生过一次内核 OOM，杀掉一个 508MB 的 node 进程。

### 3.3 结果

```
物理 903 MB（used ~848）
swap 6143 MB（used ~1147）
```

可用物理内存长期不足 100MB，应用部分驻留在 swap。**能跑，但不宽裕**；升配到 2GB 是根治方案。

## 6. systemd units

三份 unit 源文件见同目录 `systemd/`：`animetracker-business.service`、`animetracker-agent.service`、`animetracker-scheduler.service`。

要点：

| 项 | 说明 |
|----|------|
| JVM 参数 | `-Xmx192m -Xss512k -XX:MaxMetaspaceSize=96m -XX:MaxDirectMemorySize=64m -XX:+UseSerialGC -XX:+ExitOnOutOfMemoryError`。小堆 + 2 核场景 SerialGC 比 G1 省内存 |
| `MemoryMax` | business 448M / agent 320M / scheduler 512M。超限只杀本服务并由 `Restart=always` 拉起，避免内核 OOM killer 波及 MySQL 容器 |
| scheduler | 常驻（`while True` + 60s 轮询），`MemoryMax=512M` 需覆盖其 `subprocess.Popen` 派生的 importer/indexer/backfill 子树 |
| 绝对路径 | systemd 不读 `~/.bashrc`，`java` / `uv` 必须写全路径（`~/.local/opt/jdk21/bin/java`、`~/.local/bin/uv`） |
| `SuccessExitStatus=143` | SIGTERM 正常退出不算失败 |

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now animetracker-business animetracker-agent animetracker-scheduler
```

## 8. 构建与发布（服务器内构建）

工具链已在服务器就位（`~/.local/opt/jdk21`、`~/.local/opt/maven`、`node`、`~/.local/bin/uv`）。

> ⚠️ **903MB 内存下不限内存构建必 OOM**（实测前端峰值 free 仅 14MB，且 2026-10-03 已因此被杀过 node 进程）。

```bash
cd /opt/animetracker/src/AnimeTracker
git pull --ff-only

# Java（产物 app/target/app.jar，finalName=app）
cd backend/business
JAVA_HOME=$HOME/.local/opt/jdk21 PATH=$HOME/.local/opt/jdk21/bin:$HOME/.local/opt/maven/bin:$PATH \
MAVEN_OPTS="-Xmx400m -XX:MaxMetaspaceSize=128m" mvn -B -DskipTests package
cp app/target/app.jar /opt/animetracker/business/app.jar

# 前端 —— 必须分两次，合并跑必 SIGABRT(134)
cd /opt/animetracker/src/AnimeTracker/frontend
export NODE_OPTIONS="--max-old-space-size=768"    # 384 会撞 V8 堆上限
npm ci
npm run build -w client
npm run build -w admin
cp -r client/dist/* /opt/animetracker/web/client/
cp -r admin/dist/*  /opt/animetracker/web/admin/

# 生效
export UV_CACHE_DIR=/opt/animetracker/.uv-cache
cd /opt/animetracker/src/AnimeTracker/backend/agent && uv sync
sudo systemctl restart animetracker-business animetracker-agent animetracker-scheduler
sudo systemctl reload nginx
```

实测耗时：Maven 49s / client 1m20s / admin 39s / npm ci ~1min。

## 11. 已知阻塞项

### 11.1 DashScope 免费额度耗尽（影响 RAG）

```
403 AllocationQuota.FreeTierOnly
Free quota exhausted. To add funds or disable "use free tier only" mode
```

- 已切 `LLM_PROVIDER=deepseek`（余额 ¥1.33，实测对话可用）。
- **但嵌入模型只有 DashScope 提供**，故 `RAG_ENABLED=true` 当前无意义。二选一：给百炼充值 / 设 `RAG_ENABLED=false`。
- DeepSeek 余额 ¥1.33 也很低，需及时充值。

### 11.2 Resend key 为测试模式（阻断用户注册）

```
422 Invalid `to` field. Please use our testing email address instead of domains like `example.com`
```

测试模式只能发往账户本人邮箱，普通用户注册时验证码邮件发不出（接口返回 500）。需在 Resend 后台验证发信域名或换生产 key。

### 11.3 Azure NSG 未放行 8081

管理端公网不可达。两个选择：
- Azure Portal 加规则：TCP 8081，源 Any，Allow，优先级 1010。
- 更安全：不开端口，用 `ssh -i AzureServer.pem -L 8081:127.0.0.1:8081 zhaizz@104.208.115.195` 隧道访问。

### 11.4 无超管账号

`user` 表当前仅 1 个测试用户。建超管（注意 `AT_ADMIN_SUPERADMIN_ID=1`）：

```sql
UPDATE user SET role='ADMIN', email_verified=1 WHERE id=1;
```

### 11.5 无 TLS

纯 HTTP。上 HTTPS 后须把 `AT_AUTH_COOKIE_SECURE` 改回 `true`，否则 Cookie 明文暴露。

### 11.6 单实例假设

`SubprocessImportJobLauncher` 用本机 PID 文件协调，代码注释明示「多实例部署需要共享的任务协调器」，故 business/agent 不可水平扩展。

### 11.7 无数据库备份

MySQL 数据在 docker volume，未配置 `mysqldump` 定时备份。

## 12. 已修复的仓库 bug

### 12.1 agent JWT 算法硬编码导致 AI 对话 401（commit `7d758032`）

```
business (JJWT):  Keys.hmacShaKeyFor(secret) 按字节长度自动选算法
                  64 字节 → HS512，token header {"alg":"HS512"}
agent (Python):   jwt.decode(token, secret, algorithms=["HS256"])  ← 硬编码
                  → InvalidAlgorithmError → 全部 AI 对话 401
```

生产用 64 字节强密钥触发 HS512，与硬编码的 HS256 冲突，**该项在部署到服务器前不会暴露**。修复：`algorithms=["HS256","HS384","HS512"]`，并补 `backend/agent/tests/api/test_auth_deps.py`（该路径此前无任何测试覆盖，故 CI 未能拦截）。
