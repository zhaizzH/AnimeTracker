# 项目复盘

> 本复盘覆盖 AnimeTracker「番组手账」从零到完成核心功能的完整历程。项目从 2026-07-03 开始，至 2026-08-06 结束，历时约 5 周，共 **363 次提交**，技术栈覆盖 **双 React 前端**（用户端 + 运营后台）、**Spring Boot 后端** 与 **LangGraph AI Agent**。以下按技术演进、踩坑修复、流程协作、产品现状与核心收获五章展开，每章独立成篇。

## 0. 一句话总结

个人动漫追番管理平台，5 周从零做到「番剧库管理（追番 / 标签 / 用户）+ AI 对话 Agent + 运营后台」三大能力块。

## 1. 技术选型与演进

本章将回顾技术栈的选型动机与演进过程：双 React 前端、Spring Boot 后端、LangGraph Agent 的引入时机与原因，以及整体架构在开发过程中的调整脉络。

## 2. 踩坑与修复

本章将记录开发中遇到的典型坑与对应的根因修复：后端数据清洗、AI Agent 工具调用、前后端联调等环节的实际问题与解决过程。

## 3. 开发流程与协作

本章将复盘本项目的开发方式：提交习惯、重构节奏、文档沉淀等，以及这些实践对交付效率的影响。

## 4. 产品现状与路线

本章将描述当前产品已交付的能力边界（核心功能 + 运营后台预览版）与已知的未完成项，并给出后续可能的演进方向。

## 5. 核心收获 Top 3

本章将提炼整个项目中最值得沉淀的三条经验或结论，供后续项目复用。
