## §5 执行顺序与缺陷流程

Smoke（已过）→ L0（mvn test 已过，静态检查补跑）→ L2（已过）→ L1 → L3 → L4（L4 内按上表顺序，最后 L4-VISUAL-001 汇总）
缺陷：记录（ID/层/证据）→ 修复（3-Agent：Hermes 调度、Claude 复杂业务/前端、Codex 样板/防护用例；新进程新上下文）→ 回归（先受影响+冒烟，再全量）。P0/P1 修复必须配套新增防护用例。
环境问题 → LIMITED 附补测条件。脚本断言与产品实际不符时，先 curl 原始响应确认结构再定性（r3 教训）。

## §6 风险与退出标准

- 风险：导入触发耗时（recent 模式受封面代理 proxy.8000150.xyz Read timeout 拖慢，P3-OBS-01；若 >8 分钟未完成则终止该任务并标记）；AI 流耗时；内存紧张（business -Xmx1g）
- 退出标准：无未处置 P0；P1 有结论（修复或登记）
- 阻断标准：business/agent 不可用且 30 分钟无法恢复 → 停该层
