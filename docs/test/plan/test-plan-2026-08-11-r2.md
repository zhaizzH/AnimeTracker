## 0. 执行说明

1. **先读 docs**：接口文档 `docs/spec/openapi.yaml`、数据库 `docs/database/db-schema.sql`、约定 `docs/conventions/backend-conventions.md`；controller 端点已用 rg 复核。
2. **顺序执行**：Smoke Gate → L0 → L2 → L1 → L3 → L4，逐层串行；L0 失败率 >10% 阻断高层。
3. **失败分类**：环境问题 → LIMITED 不阻塞（附补测条件）；代码缺陷 → FAIL 按 P0-P3 分级记录并进入修复环节。
4. **测试账号**：client `test1/123456`，admin `admin/123456`；禁止中途注册（撞限流）。
5. **数据一致性**：L3/L4 做「前端页面 ↔ 接口返回 ↔ 数据库」三方核对；L1/L4 对 AI 助手生成文本做第四方核对。
6. **Flaky 治理**：间歇性失败标 FLAKY 独立统计，不占用常规修复循环；占比 >5% 触发上线风险提示。
7. **产出**：`docs/test/report/test-report-2026-08-11-r2.md`；修复不自动提交留人工 review；全绿后先向用户展示报告总结，用户确认后才提交。

## 5. 缺陷分级与退出标准

**缺陷分级**：
- P0 阻断：核心链路崩溃、登录失败、数据错乱、写入脏数据 → 必须修复，不放行
- P1 严重：功能可用但核心场景异常、移动端不可操作、AI 语义映射错误 → 优先修复，可协商降级开关
- P2 一般：次要布局瑕疵、非关键交互、文案错误 → 不阻塞上线，登记技术债
- P3 低优：微调视觉、非关键提示、文档问题 → 进 backlog

**退出标准**：无未处置 P0；P1 有结论；L4 浏览器实测 + 截图检查必须完成。
